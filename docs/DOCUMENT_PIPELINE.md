# NCS JD 문서 처리 파이프라인

## 목적

공공기관 채용 공고문과 사용자가 선택한 직무기술서 양식을 입력받아, Kordoc으로 문서 구조를 읽고 NCS MCP의 직접 근거를 연결한 검토용 직무기술서·직무명세서 초안을 만든다.

## 입력 역할

| 입력 | 용도 | 사실 등급 |
| --- | --- | --- |
| 채용 공고문 | 채용분야, 실제 수행업무, 자격·우대, 명시된 NCS 분류 후보 추출 | 자동 추출 후보, 사람 확인 전 미확정 |
| 직무기술서 양식 | 표 항목, 행·열·병합, 기관 서식과 출력 구조 파악 | 표현 계약, 직무 사실 근거 아님 |
| 사용자가 입력한 직무·업무 | 대상 역할 선택과 공고문 누락 보완 | `organization_input` |
| NCS MCP 응답 | 분류, 능력단위, 요소, 수행준거, 원문 KSA | 직접·보조·참고 근거 |

양식에 적혀 있던 예시 문구는 새 직무의 사실로 재사용하지 않는다. 공고문 추출값도 사람이 확인하기 전에는 NCS 검색어 후보일 뿐이다.

## 단계

```text
공고문 + 선택 양식 + 직무/업무 입력
                 │
                 ▼
          Kordoc Node bridge
  markdown / IR blocks / form schema / quality
                 │
                 ▼
       AnnouncementExtraction 후보
  role candidates / duties / qualifications /
  preferences / explicit NCS details / locators
                 │
                 ▼ 사람 확인
        ConfirmedRoleAndDuties
                 │
                 ▼
       ncs_search(scope="all")
                 │
                 ▼ 사람 선택·제외
 ncs_unit_detail(elements/criteria/ksa)
     + 선택적 ncs_analysis reference
                 │
                 ▼
  Deterministic JobProfile v1 assembler
                 │
          ┌──────┼────────┐
          ▼      ▼        ▼
        JSON    HTML     HWPX
       기준본  미리보기  표현본
```

## Kordoc 경계

- 공식 `chrisryugj/kordoc` npm 패키지 `4.2.9`를 정확히 고정한다.
- Python 프로세스는 stdin/stdout JSON 브리지만 호출하며 Node 내부 객체나 바이너리 이미지를 애플리케이션 계약으로 노출하지 않는다.
- 허용 입력은 PDF, HWP, HWPX, DOCX, TXT, PNG, JPG, WEBP다.
- 원본 파일명은 화면 표시용으로 정규화하고, 원본 바이트와 전체 parse payload를 로그에 남기지 않는다.
- 각 추출 항목은 문서 식별자, page/block locator, 추출 방식, confidence, `review_required`를 가진다.
- OCR 저품질, 다중 직무, 빈 업무, `붙임 참조`만 존재, 별도 직무기술서 필요 상태를 명시적으로 플래그한다.

## 수행업무 추출 규칙

우선순위는 다음과 같다.

1. `담당업무`, `수행업무`, `직무수행내용`, `주요업무`, `직무내용` 라벨이 있는 표 셀
2. 채용분야별 표의 역할 행과 연결된 업무 셀
3. 동일 제목의 문단·목록 구역
4. 사용자가 직접 입력한 업무

지원자격, 우대사항, 결격사유, 전형절차, 법령 인용은 수행업무에 섞지 않는다. 공고문에 여러 채용분야가 있으면 역할 후보별 업무를 먼저 분리하며, 사용자가 한 역할을 고르기 전에는 NCS 범위를 확정하지 않는다.

## NCS 조회 규칙

- 검색은 확인된 직무명과 업무 문장을 짧은 결정적 query 묶음으로 만들어 `ncs_search`에 명시적으로 전달한다.
- 대분류 → 중분류 → 소분류 → 세분류 → 능력단위 순서로 후보를 표시한다.
- 후보는 자동 선택하지 않는다. 사용자가 선택한 능력단위만 상세 근거를 불러온다.
- 수행준거 원문은 근거 패널에 두고 본문에 전부 복사하지 않는다.
- `ksa_text_raw`를 보존하며 K/S/A 유형을 바꾸지 않는다.
- 직업기초능력은 KSA에서 추론하지 않는다. 승인된 NCS 참고 근거가 없으면 비우고 검토 플래그를 남긴다.

## 출력 보장 수준

| 입력 양식 | MVP 출력 방식 | 보장 |
| --- | --- | --- |
| HWPX | form schema 또는 block patch 후 `hwpx-preserve` | 지원되는 셀 텍스트 변경 범위에서 원본 글꼴·크기·정렬·표 구조 보존 |
| HWP 5.x | 모든 대상 항목이 유일하게 일치하고 값 칸이 비어 있을 때만 HWPX로 구조 재구성, 아니면 표준 HWPX 생성 | 암호화·DRM·구조 변경은 보존 불가 상태를 보고하고 예시 값은 재사용하지 않음 |
| PDF | 모든 대상 항목이 유일하게 일치하고 값 칸이 비어 있을 때만 HWPX로 구조 재구성, 아니면 표준 HWPX 생성 | 원본 픽셀·글꼴의 완전 복제는 보장하지 않고 예시 값은 재사용하지 않음 |
| 양식 없음 | 내장 표준 `NCS 기반 채용 직무 설명자료` HWPX 생성 | 분류체계, 능력단위, 수행내용, K/S/A, 직업기초능력, 비고·근거 행 제공 |

모든 HWPX는 구조 검증과 렌더 검토를 통과한 뒤 제공한다. HWPX 안의 내용은 항상 동일한 `JobProfile v1` JSON에서 유도되어야 한다.

## 첫 종단 시나리오

`전기시설 유지보수`를 복합 직무 회귀 시나리오로 사용한다.

1. `19. 전기·전자 → 01. 전기 → 07. 전기공사 → 01. 내선공사`
2. `15. 기계 → 05. 기계장치설치 → 01. 기계장비설치·정비 → 07. 승강기설치·정비`
3. `05. 법률·경찰·소방·교도·국방 → 02. 소방방재 → 01. 소방 → 04. 소방안전관리`

위 분류는 회귀 fixture의 기대 후보이며, 실제 문서 생성에서는 현재 NCS MCP 응답과 사용자 선택을 다시 확인한다.
