# NCS JD 구현 계획

기준일: 2026-08-13

## 1. 목표

사용자가 공공기관 채용 공고문과 원하는 직무기술서 양식(PDF/HWP/HWPX)을 올리고 만들 직무·실제 수행업무를 입력하면, Kordoc으로 업무와 양식 구조를 추출하고 사람이 NCS 범위와 능력단위를 확인한 뒤 NCS 근거가 추적되는 직무기술서와 직무명세서 초안을 로컬에서 생성한다.

첫 MVP는 다음 질문에 답해야 한다.

1. Kordoc이 공고문에서 채용분야와 실제 수행업무를 원문 위치와 함께 추출할 수 있는가?
2. 사용자가 자신의 직무에 맞는 NCS 범위를 찾을 수 있는가?
3. 어떤 능력단위가 문서에 포함되는지 사람이 통제할 수 있는가?
4. 생성 문장이 공고문·조직 입력·NCS 중 어디에서 왔는지 확인할 수 있는가?
5. 선택한 양식 또는 표준 양식으로 검증된 HWPX를 만들 수 있는가?
6. LLM 없이도 검토 가능한 초안을 만들 수 있는가?

## 2. 확정 결정

### 프로젝트 분리

- 신규 프로젝트 루트: `C:\workspace\NCS_JD`
- 원천·온톨로지·수집 시스템: `C:\workspace\NCS_MCP`
- 두 프로젝트의 런타임 경계: 로컬 streamable HTTP MCP
- 기본 MCP 주소: `http://127.0.0.1:8766/mcp`
- health/readiness: `http://127.0.0.1:8766/health`, `http://127.0.0.1:8766/ready`

### 기술 스택

- Python 3.12
- FastAPI: 로컬 애플리케이션 서버와 내부 API
- Jinja2 + HTMX: 별도 프런트엔드 빌드가 없는 다단계 wizard
- Pydantic: `JobProfile v1` 계약과 입출력 검증
- Python MCP SDK: streamable HTTP MCP 호출
- pytest: 단위·계약·시나리오 테스트
- JSON 파일: MVP draft 저장 및 내보내기
- Kordoc 4.2.9: 공고문·양식 파싱과 HWPX 생성/검증, Node JSON bridge로 격리

### 생성 전략

- 1단계: Kordoc 공고문·양식 파싱과 자동 추출 후보 생성
- 2단계: 사람의 역할·업무 확인과 NCS 범위·능력단위 선택
- 3단계: NCS 직접 근거 수집
- 4단계: 규칙 기반 결정적 초안 조립
- 5단계: JSON/HTML/HWPX 검토와 내보내기
- 6단계: 결정적 초안을 그대로 출력하고, 로그인된 CLI가 있을 때만 양식 필드명 매핑 보완

`로컬 전용` 실행 경로의 직무·NCS 근거 생성은 생성형 AI를 호출하지 않는다. 양식을 올렸고 CLI가 로그인된 요청만 양식 필드명과 제한된 예시값을 보내 필드 연결을 보완한다. 이 단계는 JobProfile을 읽거나 수정하지 않으며, 어떤 경로에서도 사용자에게 API 키를 요구하지 않는다.

생성기로 좁혔으므로, 실제 동작 범위는 8절 기능 항목과 12절을 기준으로 읽는다.

- 세분류 및 능력단위 후보 제시
- 능력단위 다중 선택과 제외
- 직급·목표 숙련수준 입력
- 조직 고유 책임, 제외 업무, KPI, 보고관계 입력
- 직무기술서와 직무명세서 분리 생성

- 전기시설 유지보수 복합 직무 중심 첫 품질 시나리오

- 임의 PDF/HWP 양식의 픽셀 단위 완전 복제
- 다중 사용자·권한·동시편집
- 외부 공개 호스팅
- SQF·학습모듈 기반 추천
- 전 NCS 분야의 동일 수준 품질보증

## 4. 사용자 흐름

### 1단계: 공고문·양식 업로드와 Kordoc 추출

사용자는 공고문, 선택 양식, 만들 직무와 실제 수행업무를 입력한다. 앱은 Kordoc 결과에서 채용분야, 수행업무, 자격·우대, 명시된 NCS 세분류를 후보로 추출하고 원문 page/block 위치와 함께 보여준다. 추출값은 사람이 확인하기 전에는 NCS 검색에 사용하지 않는다.

### 2단계: 직무 검색

사용자가 `인사담당자`, `채용담당자`, `교육담당자` 같은 직무명을 입력한다.

앱은 `ncs_search` 결과를 다음 단위로 묶어 제시한다.

- 대분류 / 중분류 / 소분류 / 세분류
- 능력단위명과 수준
- NCS 직무 정의 또는 능력단위 정의 미리보기

앱은 후보를 추천할 수 있지만 자동 확정하지 않는다.

### 3단계: NCS 범위 선택

사용자는 다음을 직접 선택한다.

- 주 세분류
- 포함할 능력단위
- 제외할 능력단위
- 대상 직급 또는 숙련수준

직무 하나가 여러 세분류에 걸칠 수 있도록 다중 범위를 허용한다. NCS 세분류를 조직 직무와 동일한 개념으로 간주하지 않는다.

### 4단계: 조직 맥락 입력

MVP 입력 필드:

- 조직 내 직무명
- 소속 부서
- 직무 목적 보완 문장
- 핵심 책임
- 제외 업무
- 의사결정 권한
- KPI 또는 기대 성과
- 주요 협업 대상
- 보고관계
- 대상 직급 또는 숙련수준

비어 있는 조직 필드는 NCS 정보로 추정해 채우지 않는다.

### 5단계: 초안 생성

결정적 조립기는 다음 매핑을 사용한다.

| NCS 근거 | 문서 사용 | 규칙 |
| --- | --- | --- |
| 세분류 `duty_def_api` | 직무 목적 후보 | 조직 입력과 병합하되 원문 출처 보존 |
| 능력단위명·정의 | 주요 책무 | 사용자가 선택한 단위만 포함 |
| 능력단위요소 | 세부 과업 그룹 | 중복 정규화 후 15~25개 이내 권장 |
| 수행준거 | 과업 설명 근거 | 본문 전체 나열 금지, 근거 패널에서 확인 |
| 원문 KSA | 직무명세서 K/S/A | 유형별 중복 제거, 원문 참조 유지 |
| 능력단위 수준 | 목표 숙련수준 참고 | 조직 직급과 동일시하지 않음 |
| 자격·직업기초능력 | 참고 근거 | 필수조건으로 자동 승격 금지 |
| 조직 입력 | KPI·권한·보고관계 | `organization_input`으로 표시 |

### 6단계: 검토와 내보내기

화면은 다음 두 패널을 제공한다.

- 문서 패널: 사용자가 읽고 편집할 수 있는 초안
- 근거 패널: 선택 문장의 NCS 원천 ID, 원문, 근거 등급

내보내기는 `JobProfile v1` JSON, 인쇄 가능한 HTML, Kordoc으로 생성·검증한 HWPX를 지원한다. JSON이 기준본이다.

## 6. MCP 호출 계획

첫 MVP는 자연어 라우터를 사용하지 않고 명시적인 도구를 호출한다.

1. `ncs_search(query, scope="all", limit=20)`
2. 선택한 각 단위에 `ncs_unit_detail(unit_code, include=["elements", "criteria", "ksa"])`
3. 사용자가 참고 근거를 요청한 경우에만 `ncs_analysis`

NCS MCP가 준비되지 않은 경우 생성 버튼을 비활성화하고 연결 복구 방법을 보여준다. 이미 받아 둔 draft는 MCP 장애 중에도 열람할 수 있어야 한다.

## 7. 10일 MVP 실행계획

### 1일차 — 프로젝트 기반과 계약

- Python 패키지, 테스트, 환경설정 구조 생성
- `JobProfile v1` Pydantic 모델 구현
- `NcsSourcePort` 인터페이스 정의
- 샘플 JSON과 schema validation 테스트

완료 기준: 샘플 JobProfile이 검증되고 JSON round-trip이 통과한다.

### 2일차 — MCP 연결

- streamable HTTP MCP client adapter
- health/readiness 확인
- timeout, 오류 매핑, 비밀값 없는 로그
- mock MCP contract test

완료 기준: 로컬 NCS MCP에서 검색 결과를 가져오고 장애를 구조화 오류로 변환한다.

### 3일차 — 검색과 범위 후보

- 직무명 검색
- 분류/능력단위 후보 그룹화
- 선택·제외 모델
- 전 범위 검색과 인사 샘플 테스트

완료 기준: `인사담당자` 검색에서 인사 세분류와 관련 능력단위를 선택할 수 있다.

### 4일차 — Evidence Bundle

- 선택 단위별 element/criteria/KSA 수집
- KSA 유형 정규화와 정확 중복 제거
- 원천 참조 생성
- 직접/보조/조직 입력 근거 등급

완료 기준: 모든 bundle 항목이 source ID와 원문을 가진다.

### 5일차 — 결정적 조립기

- 직무 목적, 책무, 과업, K/S/A 생성 규칙
- 조직 입력 병합
- 제외 업무 필터
- review flag 생성

완료 기준: 동일 입력이 동일 JSON을 만들고, 근거 없는 사실을 생성하지 않는다.

### 6일차 — 로컬 웹 wizard

- 검색 → 후보 선택 → 조직 맥락의 3단계 화면
- 선택 상태 보존
- 잘못된 단계 이동과 빈 선택 방지

완료 기준: 브라우저에서 한 흐름으로 초안 생성을 완료한다.

### 7일차 — 미리보기와 provenance

- JD/Person Specification 분리 표시
- 문장별 근거 패널
- 검토 플래그와 참고 근거 표시
- 원문 과잉 노출 방지를 위한 접기 UI

완료 기준: 사용자가 각 NCS 기반 항목의 출처를 2회 이내 클릭으로 확인한다.

### 8일차 — 저장과 내보내기

- draft JSON 저장·불러오기
- 파일명 안전 처리
- HTML 인쇄 뷰
- NCS 응답 원문 전체가 로그나 HTML에 불필요하게 노출되지 않도록 제한

완료 기준: 초안을 닫았다가 다시 열고 동일한 provenance를 확인한다.

### 9일차 — 전기시설 유지보수 시나리오 평가

- 인사 종합: 인사기획·직무관리·채용·평가 조합
- 채용 담당: 인력채용 중심
- 교육 담당: 교육훈련운영 중심
- 잘못된 범위, 빈 결과, 제외 업무 회귀 테스트

완료 기준: 세 시나리오의 기대 능력단위·제외 단위·근거 완전성 검사가 통과한다.

### 10일차 — 사용성 점검과 인계

- 처음 사용하는 사람 기준 walkthrough
- Windows 실행 스크립트
- 설치·실행·문제 해결 문서
- 남은 위험과 Phase 2 backlog 확정

완료 기준: 새 환경에서 문서만 보고 앱과 NCS MCP를 로컬 실행해 샘플 초안을 생성한다.

## 8. MVP 수용 기준

### 기능

- 공고문에서 수행업무 후보를 원문 위치와 함께 추출하고, 생성 전 검토 화면에서 사람이 수정·확정할 수 있다.
- 확정한 업무에서 세분류와 능력단위를 결정적 규칙으로 선택하고, 선택 근거를 결과 문서에 남긴다.
- 직무기술서와 직무명세서 항목이 분리되어 생성된다.
- 표준 HWPX와 업로드한 기관 양식 양쪽으로 출력한다.
- 에이전트 초안을 JSON으로 저장하고 다시 열 수 있으며, 검토 화면을 인쇄할 수 있다.

다음 세 항목은 미구현이 아니라 의도적으로 제외했다. 단계별 마법사를 걷어내고 공고문
하나로 끝나는 자동 생성기로 좁힌 결과이며, `tests/web/test_app.py`가 해당 화면 문구가
다시 등장하지 않는지 검사한다.

- 대분류·중분류·소분류·세분류 수동 선택 화면
- 전체 NCS 검색 화면. `/api/ncs/search`는 남아 있으나 UI에 연결하지 않는다.
- 능력단위 포함·제외 화면

초안 JSON 저장·불러오기와 인쇄는 에이전트 경로에만 있다. 결정적 로컬 생성은 HWPX만
내보낸다.

### 근거

- 모든 `ncs_direct` 항목에 유효한 source reference가 있다.
- 수행준거 원문은 생성 본문이 아니라 결과 문서의 `비고/근거` 항목에 출처 ID로 남는다.
- 조직 입력과 NCS 근거를 `JobProfile`과 결과 문서에서 구분한다.
- 자격과 직업기초능력은 `reference`보다 강한 등급을 받지 않는다.

### 안전

- NCS DB에 대한 쓰기 코드가 없다.
- 자동 `human_reviewed`, `accepted`, `reviewed` 상태가 없다.
- 근거 없는 학력·자격·경력연수·법적 의무를 생성하지 않는다.
- 문서는 공식 자격 인정이나 채용 결정이 아니라 초안임을 표시한다.

### 품질

- LLM OFF 동일 입력의 구조화 출력이 결정적이다.
- 전기시설 유지보수의 내선공사·승강기설치·정비·소방안전관리 복합 시나리오가 회귀 테스트로 고정된다.
- MCP 장애와 빈 검색 결과가 사용자에게 복구 가능한 메시지로 표시된다.
- 근거 패널을 걷어냈으므로, 직무기술서와 직무명세서 각각의 `비고/근거` 항목이 출처 ID를 싣고 근거가 약하거나 없는 항목은 같은 자리에 review flag 사유를 남긴다.

## 9. 데이터 품질 처리

- `duty_def_api`, 능력단위 정의, 요소, 수행준거, 원문 KSA를 직접 근거로 우선한다.
- 자동 정제 필드는 원문과 함께 있을 때만 표시한다.
- 온톨로지 정의 후보는 문장 생성 원천으로 사용하지 않는다.
- 자격 수집이 불완전하면 `qualification_evidence_incomplete` 플래그를 남긴다.
- 직업기초능력 10개 상위 범주는 상세 직무역량을 대체하지 않는다.
- 능력단위 수준은 조직 직급이나 급여등급과 자동 대응시키지 않는다.

8. 완료: 에이전트 초안의 로컬 JSON 저장·재열기와 검토용 인쇄 화면

에이전트 초안 JSON은 서버에 남기지 않고 사용자가 고른 위치에 내려받는다. 파일에는
`schema` 태그, 검토한 항목값, 조회한 능력단위 코드, 올린 기관 양식이 함께 담기므로
재열기 후 공고문이나 재실행 없이 같은 양식으로 다시 HWPX를 만들 수 있다. 스키마
태그가 다른 파일은 화면 상태를 바꾸지 않고 거부한다.
